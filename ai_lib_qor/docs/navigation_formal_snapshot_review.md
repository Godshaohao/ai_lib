# 工作台导航与正式快照审查

## 审查问题

工程师选择 Vendor / SourceLibrary / Business IP 后，应能回答：文件来自哪些交付、当前 IP 的有效文件集是什么、正式阶段记录了什么、应该执行哪次检查、结果在哪里。公共 Formal NL 与单个 IP 的有效版本是不同对象。

## 重组前的审查

| 现有入口 | 代码实际表达 | 问题 |
|---|---|---|
| 检查工作区 | 文件定位、交付对比、正式来源、手动检查、运行记录五个子页 | 混合来源查询、检查执行和运行历史；前三项只读，不执行质量检查，名称容易让人以为进入后正在检查。 |
| 有效版本 | 浏览某 IP 的有效版本、成员及采纳事件 | 对象边界明确，但与“库与版本”中的有效版本列表重复。 |
| 库与版本 | 已登记 IP 的有效版本检查、源库交付版本、解析证据 | 既是版本目录又是运行入口；与有效版本页和手动检查重叠。 |
| 正式 NL / 正式来源 | 两个入口均指向同一个 `view=formal` | 同一页面被放在两层；可能误认为一个是公共正式库，一个是当前 IP 的正式来源。 |
| 输出目录 / 运行记录 | 都能访问运行产物；运行记录默认当前 IP，输出目录是全部运行 | 使用范围不一致，但两者命名没有明确“当前 IP / 全部”。 |
| 发现 / 登记 RAW | 当前是未迁移的说明页 | 占据一级操作位置，但尚不能完成登记。 |

## 已采用的信息架构

```text
左侧：Vendor → SourceLibrary → Business IP

一级任务：
├─ 文件与交付       # 源库观察、交付对比；明确尚未按 IP 过滤
├─ IP 有效版本      # 版本、成员、采纳；链接到对应版本的检查
├─ 正式库快照       # 公共 Formal NL，独立于 IP；可查看声明范围
├─ 检查与报告       # 单版本检查、整体 IP 检查、当前 IP 运行和输出
└─ 数据登记         # RAW/正式来源配置；未迁移时清楚标明
```

当前按此结构组织页面；旧 `view=catalog` 与 `view=manual` 保持兼容并显示“检查与报告”。关键是同一业务任务应有一个主要入口。文件与交付页面提供证据给检查，但查询本身不是检查。正式快照可以被有效版本引用，也可以独立存在；选择某 IP 不等于自动限定正式快照范围。运行记录是检查的结果，输出目录是产物位置。

## 正式快照组件（当前已接入只读页面）

- **阶段与快照列表**：按 `formal_nl_id` 分组，显示每次 `formal_snapshot_id`、观察时间及声明源库；选择后展示该次记录。按时间排序仅为浏览，不推断“当前”或“最新”。
- **快照上下文**：展示 `source_root`、`observed_at`、`scope.source_library_ids`、`scope.views`、`coverage` 及可用的 `previous_snapshot_id`。前序引用可唯一解析时可点击，缺失或重复则提示。
- **来源表与筛选**：按文件位/路径/ID 和匹配状态过滤 `linked_files`，显示正式链接、解析目标和记录的 RAW 引用。数量是所选快照的记录数，不推断其他阶段或其他 IP。
- **异常处理**：多个记录有相同的阶段/快照身份时不得自动选一个；来源未知、部分覆盖和未找到前序均保持可见。

这些组件读取已保存的 `formal_snapshot.v1`。当前未实现正式 `index.json` 的生成和维护，也未实现网页扫描、刷新、创建或采纳操作。
