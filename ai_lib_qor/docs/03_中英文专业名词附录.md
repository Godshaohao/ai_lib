# ai_lib_qor 中英文术语附录 · v3.0

> 术语使用规则：用户界面优先中文，括号可附短英文；代码、JSON 字段沿用英文稳定名。避免同时使用多套近义词。下表将术语分为业务对象、数据记录、行为与状态、技术内部术语。

## A. 用户必须理解的业务词（界面一级导航建议只用这些）

| 中文推荐名称 | English | 统一含义 | 不建议的混用方式 |
|---|---|---|---|
| 供应商 | Vendor | 提供原始交付的公司或组织 | 不与 SourceLibrary 同义 |
| 原始库 / 来源库 | Source Library | 一个有稳定身份的 RAW 文件集合与交付历史 | 不叫 BusinessIP，也不是某一次交付 |
| 业务 IP | Business IP | 验收、归属与业务操作主体，可关联多个来源库 | 不强制当作一个 Vendor Library 的永久唯一子对象 |
| 交付 | Delivery | 一次供应商交付事件（V07/V08 只是外部版本名） | 不叫 Effective Version |
| 交付版本 | Supplier Version | 供应商原始版本标签 V07、V08 | 不等于 `delivery_id` |
| 正式 NL | Formal NL | 实际 Release/Link 环境的正式库集合，如 NL2.5.3 | 不等于当前有效版本 |
| 正式文件快照 | Formal Snapshot | 正式 NL 在一次确认时刻的固定文件引用状态 | 不叫 g1/g2，正式标签不等于快照 ID |
| 有效文件集 | Effective Set | 一个 IP（或无归属库）独立维护的一套有效文件组合系列 | 不与单个 Rev 混用 |
| 有效版本 | Effective Version | 有效文件集的一个完整不可变文件组合 Rev | UI 建议叫 `Rev 008` |
| 文件变化 | File Changes | 文件来源、Macro/Pin/Cell 内容的前后差异 | 不等同于质量不合格 |
| 质量检查 | Quality Checks | LEF–Liberty Pin、结构/文件等规则判定 | 不代替采纳决定 |
| 采纳 / 回退 | Accept / Rollback | 业务上采用哪个有效版本 | 不由新交付/新正式 Snapshot 自动触发 |

## B. 数据契约名（开发者使用）

| JSON/技术名 | 页面展示 | 一句话职责 | 保存位置 |
|---|---|---|---|
| `DeliveryRecord` | 本次交付文件 | 某次交付具体有哪些物理文件 | `<delivery_id>/delivery.json` |
| `FormalSnapshot` | 正式库文件记录 | 某次正式 NL 固定状态中的真实链接 | `formal_nl/.../snapshots/*.json` |
| `EffectiveVersion` | 有效版本 | 一个 Rev 的完整成员及相对上一 Rev 的采用变化 | `effective/versions/rev_*.json` |
| `CheckResult` | 文件变化与检查结果 | 针对特定交付或有效 Rev 的一次检查 | `checks/.../run_*.json` |
| `FileFacts` | 文件解析结果 | LEF Macro/Pin、Liberty Cell/Pin 等已抽取事实 | 现有 Parser / `file_facts/` |
| `EffectiveIndex` | 当前版本 | 最新计算 Rev、当前采纳 Rev 的查询入口 | `effective/index.json` |
| `AcceptanceEvent` | 版本采纳记录 | 一次明确的人工采纳、撤销或回退事件 | `effective/acceptance.jsonl`（可选） |

## C. 重要技术字段

| 字段 / 术语 | 中文解释 | 使用与边界 |
|---|---|---|
| `vendor_id` | 供应商 ID | 跨文件稳定，不要仅凭显示名称连接 |
| `source_library_id` | 原始库 ID | 物理文件归属来源库 |
| `business_ip_id` | 业务 IP ID | 管理主体，可能跨来源库 |
| `home_source_library_id` | 主存放库 ID | 仅指定有效版本的权威存放位置，不意味着所有成员来源该库 |
| `delivery_id` | 交付事件 ID | 同名 V08 再交付时不得沿用旧 ID |
| `supplier_version` | 供应商交付标签 | 可长、可重复，界面原样显示 |
| `delivery_order` | 已确认交付顺序 | Latest/Previous 以此为优先顺序 |
| `file_key` | 逻辑文件位标识 | 对应跨版本同一 LEF/Liberty 角色；需包含 Corner/Mode 等区分 |
| `file_id` | 单次记录中的文件行 ID | 只有配合 delivery/snapshot 才全局唯一 |
| `source_ref` | 文件来源引用 | 指向特定交付行或正式快照行；不能指向可变的 latest |
| `formal_nl_id` | 正式 NL 名称/ID | NL2.5.3 标签可长期不变 |
| `formal_snapshot_id` | 正式状态快照 ID | 链接发生变化则新建固定 ID |
| `effective_set_id` | 有效文件集 ID | 默认一 IP 一套，必要时支持多套 |
| `revision_id` | 有效版本 ID | 格式如 rev_0008，UI 叫 Rev 008 |
| `parent_revision_id` | 前驱有效版本 | 版本继承关系，不是交付历史中的上一次 V |
| `members` | 有效成员全集 | 每个 Rev 必须能独立还原所有文件来源 |
| `changes` | 本次成员采用变化 | ADDED/REPLACED/REMOVED，不代表 Macro 内容改变 |
| `analysis` | 分析 | 建议不用作目录顶层混合一切；本文统一 `checks` 保存具体执行结果 |
| `review` | 审查/验收活动 | 既有 Python 模块可保留；新持久结果具体叫 CheckResult |
| `file_changes` | 文件内容/来源差异 | `source_changed` 与 `content_status` 必须分开 |
| `object_changes` | Macro/Pin/Cell 属性变化 | 有对象名、属性、前后值与对应 Parser 证据 |
| `parse_status` | 解析完成状态 | 只对 `covered_sections` 声明范围有效 |
| `coverage` | 检查覆盖范围 | 未覆盖不能称 PASS |
| `current_accepted_revision` | 当前已采纳版本 | 与最新计算 Rev、正式 NL 当前链接彼此独立 |
| `latest_calculated_revision` | 最新计算版本 | 只是当前入口，不代表业务已接受 |
| `snapshot` | 固定状态快照 | **仅**用于固定 Formal NL 状态，不对全部对象滥用 |
| `projection` | 派生查询视图 | 缓存、页面数据可重建，不是权威历史 |
| `idempotent update` | 幂等更新 | 同一交付/运行重复执行不产生重复对象 |
| `reconciliation` | 历史核对 | 定期检查旧路径是否漂移，不等于每天全量重新解析 |

## D. 工程专有名词

| English | 中文 | 对象含义 |
|---|---|---|
| LEF | 版图抽象文件 | Macro、SIZE、PIN、OBS、SITE 等物理接口事实 |
| Liberty (`.lib`) | 时序库文件 | Library、Cell、Pin、时序/功耗模型等；本契约示例仅演示 Cell/Pin |
| Macro | 宏单元 | LEF 中定义的物理宏对象 |
| Cell | 库单元 | Liberty 中的 cell 对象，不要与 LEF Macro 在存储层强制合成同一对象 |
| Pin | 引脚 | 需要区分方向、Signal/Power/Ground、PG Pin 和物理/逻辑接口 |
| Corner | 工艺/电压/温度角及 RC 条件 | 影响 Liberty 等文件的逻辑身份 |
| View | 库视图 | LEF/Liberty/Verilog/CDL/SDC/UPF/CPF/SPEF/DB/GDS 等 |
| QoR | 质量指标 | 指标口径明确才称 QoR；不能把文件数变化简单称作 PPA 改善 |
| RAW-first | 优先依据 RAW 文件历史 | 不依赖正式 NL 也能定位和比较最新/次新交付文件 |
| Delta | 差异 | 指明是“采用来源差异”还是“解析内容差异” |

## E. 常见说法对照（供口头沟通）

- 不说“E0、g1、FormalReference 当前快照落后”，改说“正式 NL 现在链接 V07 文件，最新有效版本已经计算采用 V08，但尚未采纳”。
- 不说“`source_ref` changed, content delta present”，改说“文件来源更新了，Macro SIZE 已确认变化”。
- 不说“Review Pass so latest promoted”，改说“Pin 检查通过，版本是否采纳仍需单独决定”。
- 不说“重新跑了所有 JSON”，改说“只处理这次新交付的两份文件，旧版本保持不变”。
- 不说“Latest/Next-latest Delivery Version”，改说“同一个文件最近两次实际出现的来源版本”；交付未包含此文件不算一次出现。
