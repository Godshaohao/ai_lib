# 历史完整性整改与剩余边界

## Formal 观察

盘点时把所有可读取的链接观察（含已匹配、断链、未匹配、无法唯一归属和未展开的目录链接）写入工作目录 `formal_observations.tsv`。每次观察附时间、NL 来源和 COMPLETE / PARTIAL；它是观察日志，不改变 Formal JSON 契约。遇到目录读取错误或未解析链接时不发布新的 Formal 快照，已有快照和指针保持不变。一次不完整观察不能用来断言旧链接消失。普通文件仍作为警告处理；本记录针对链接，不代表文件内容一致。

## RAW 观察

每库 `raw_observations.tsv` 保存每个来源版本首次成功观察到的文件路径、大小和 `mtime_ns`。以后大小或修改时间变化，持续提示疑似原地修改；FileFacts 遇到该变化时拒绝将当前文件作为该观察时的文件解析。首次观察可能晚于交付登记时间，不是历史字节证据；没有变化也不证明内容一致。没有进行扫描内容哈希，也无法据此恢复已被覆盖的历史文件。

## 索引和查询

索引刷新只接受既有历史数组相对顺序保持不变的新增记录；历史顺序改变会拒绝覆盖，需单独制定受控修订流程。Schema 明确每类历史条目的必要字段。新链的 Web、检查和文件选择通过 `PathDataQuery`；为了确保一致性，普通查询当前仍完整重建比较，还不是高性能增量查询。

## 历史迁移

迁移器可读取符合契约的 `delivery_record.v1`、过渡七字段及其映射、`effective_version.v1` 和同库 `effective.simple.v2`；只写独立目标目录。无法归属或缺目标的旧 Formal 链接保存在 `formal_observations.tsv`，标记 PARTIAL，不虚构来源，也不发布 latest Formal 指针。跨库有效成员仍会停止迁移。旧采纳事件重放校验后写入 `legacy_acceptance.tsv`，不保留旧事件 ID；返回旧采纳版本，如果与新目录最新发布版本不同则明确警告。该表为历史记录，不是新流程独立的当前采纳指针。

旧 `file_index.v3` 存在时，按每个 View / 路径对 RAW、Formal 和 Effective 关系逐条对照，输出 `file_index_reconciliation.tsv`：MATCH、MISSING、ADDED、UNRESOLVED 和 ORDER_DIFFERENT；重复项按数量核对，并比较同一路径中 RAW 与 Effective 的历史相对顺序。Formal 对照包括观察时间、链接路径、链接目标和解析路径。无法识别旧索引格式时拒绝声称对账完成。比较的是归档来源关系，不代表现场链接或字节一致；由于旧新索引的匹配范围不同，新增不自动代表新交付。

本次以独立目录试验本地备份：五份交付、一份 Formal、两个版本分别保留一和两个成员；旧采纳 rev_0001、新最新发布 rev_0002 的差异会报告。v1 输入测试使用从旧归档映射还原的记录与独立合成的完整 v1 契约；该演练不等于所有真实旧库或跨库历史均通过迁移。

## 有效版本交互

路径式工作台可从文件历史批量选用来源或移除成员，预览并一次发布；也可预览恢复已有 Revision。用户确认时按预览父版本进行乐观并发校验，创建新 Revision，不修改旧版本。恢复预览会提示已排除来源和当前不可用文件；用户确认是对恢复操作的明确选择。批量选择当前页面最多 50 项且选择内容不超过 2000 字节，同一文件不能重复选择；跨页需分批处理。

每库 `effective_operations.tsv` 记录版本发布的 INTENT 和结果，包括操作来源（本地、CLI、Web 或自动处理）、父版本、目标版本及实际成员变化。INTERRUPTED 不代表没有创建版本；自动更新重试修复指针并成功刷新索引后会追加 RECOVERED。显式应用和恢复的 REJECTED、UNCHANGED 也会记录，预览不写审计。该记录不是用户身份认证，不可将 `web` / `cli` 误认为真实操作者。视觉验收受当前本地浏览器不可用限制。
