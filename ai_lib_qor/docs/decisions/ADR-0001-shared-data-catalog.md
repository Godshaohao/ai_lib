# ADR-0001: 多 HTML 共用业务数据与统一查询语义

- 状态：ACCEPTED（**设计原则确认**，不代表数据库/缓存实现已批准）
- 日期：2026-11-18
- 范围：ai_lib_qor 的 RAW/Formal、有效版本、FileFacts、Check、Web/Excel/Agent 数据访问
- 依据：用户确认的架构讨论；实际代码与回归请以当前工作区为准

## 背景

系统将提供多个 HTML、Excel 报告和 Agent。若每个页面在请求中重新扫描 RAW/Formal、解析 LEF/Liberty、推断“最新”或合成有效版本，将形成重复成本、状态不一致和不可控副作用。

## 决策

1. 来源扫描、登记、版本构建和检查属于独立应用命令；业务产物持久保存。
2. 多种展示共享文件/版本/Run 身份、对象关系与查询语义，以 LibraryCatalog/Query Service 对外提供。
3. 打开页面只读查询，不隐式执行来源扫描、版本写入或批量检查。
4. 动态工作台读取已发布状态；静态 HTML/Excel 绑定明确的版本/Run/规则/证据。
5. 初期以既有 JSON/JSONL 权威历史及共享查询模型为基础。是否物化、如何缓存、是否 SQLite 由单独 ADR 决定。

## 影响

- 新 HTML 优先增加 Query/View；缺失事实时追踪生成者并复用已有解析器。
- 允许轻量查询时聚合，但不得混同于原始业务处理。
- 维护投影时必须有可重建、一致性和错误状态。

## 非目标

不强制完整 CQRS、Event Sourcing、数据库迁移、消息队列、复杂前端 MVVM 或微服务。

## 验收

新增两个不同 HTML 查询同一 IP、Rev 和 Run，关键身份、来源与检查结果一致；Web GET 不写 RAW、版本或检查；重新渲染报告不重跑扫描和解析。
