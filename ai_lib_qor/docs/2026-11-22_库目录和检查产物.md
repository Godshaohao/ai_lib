# 库目录和检查产物（2026-11-22）

新写入使用 `work/libraries/<vendor>/<library>/` 下的 `delivery/`、`formal/`、`effective/` 和 `log/`；根目录保留 `file_index.json` 和 `latest_*.json/xlsx` 相对软链接。`.versions.lock` 是并发锁，不是业务数据。自动更新状态和操作审计位于 `log/`。历史平铺归档仍可读取。

- `latest_delivery.json` 指已确认排序的最新交付；`latest_formal_<NL>.json` 指该 NL 阶段最新快照；`latest_effective.json` 指最新发布的有效版本。
- `latest_check.json` 和 `latest_check.xlsx` 指最近完成的同一次单版本检查，可能不是最新有效版本。`latest_overall.xlsx` 指最近生成的整体报告。
- `log/check_rev_<编号>_run_<UUID>.json` 与同名 `.xlsx` 为同一次检查；JSON 的 `facts_evidence` 内嵌本次使用的解析事实，`facts_refs` 是其中的键。显式导出 Facts 仍可生成独立 JSON。
- `log/runs.jsonl` 逐次追加检查和整体汇总记录。整体报告默认选取每个版本最近保存的单版本结果；缺少结果标记为 `NOT_CHECKED`。复用历史结果不证明当前 RAW 字节未发生变化。需要全部重跑时使用 CLI `minimal-check-library --rerun` 或页面上的重新检查按钮。
- `path-migrate-layout --work ... --vendor ... --library ...` 在锁内迁移平铺的 Delivery、Formal、Effective 和相关操作日志，检查迁移前后索引一致；目标冲突时报错。为避免破坏旧 JSON 对绝对路径与独立 Facts 的引用，旧检查、Excel 和 Facts 暂保留原位置，查询和下载继续兼容。不得把这些旧文件直接移动或删除。

迁移不会扫描或修改 RAW / Formal 来源，不重写不可变归档内容。来源目录变化、检查结论和人工采纳是不同事实；检查运行成功不代表质量规则全部通过。
