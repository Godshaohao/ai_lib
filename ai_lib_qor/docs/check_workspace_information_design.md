# 检查工作区信息设计

目标：工程师选定 Vendor / SourceLibrary / IP 后，能定位文件、比较两次交付、核对已保存的正式来源、执行明确的版本检查并找到运行输出。页面使用 work 目录的 v3 记录和工作台运行状态；不把观察或执行完成当作质量通过。

| 页面 | 人要回答的问题 | 主要组件与操作 | 数据依据及边界 |
|---|---|---|---|
| 文件定位 | 已登记交付中，这个文件出现在哪里？ | 源库和数量概览、搜索/View 筛选、文件表与交付历史展开 | `delivery_record.files` 和 delivery_order；尚未按 IP 过滤或确认盘点完整；重复文件位显示不唯一 |
| 交付对比 | 两次交付各自列了哪些文件位？ | 基准/目标选择器、逐文件位表和清单关系 | 已解析的两次 Delivery；未列出不代表删除，均列出不代表内容相同；重复文件位不静默覆盖 |
| 正式来源 | 某次正式快照记录了哪些链接和来源？ | 快照选择器、观察时间/范围/覆盖、链接来源表 | `formal_snapshot.v1`；显示完整快照及声明范围，不冒充仅当前 IP，也不扫描当前目录 |
| 手动检查 | 当前 IP 的哪个版本可以运行什么计划？ | 按有效版本列计划和运行按钮；未绑定 IP 的高级入口单独折叠 | 只有目标版本 JSON 完全一致的计划走绑定入口；事实及检查范围仍在运行时验证 |
| 运行记录 | 当前 IP 运行过什么，输出在哪？ | 默认当前 IP、可切换全部、状态表、输出链接 | 按 vendor/library/IP 三元身份精确过滤；未绑定不按同名推断；完成是执行状态而非质量通过 |

所有筛选都是对已保存的数据；缺失、未解析、范围不完整和没有运行均保留可辨识状态。旧版 RAW 刷新、一键自动计划、后台任务及完整 IP 归属仍未完成。
