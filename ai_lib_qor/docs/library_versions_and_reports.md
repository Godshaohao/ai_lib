# 库与版本：两类检查与输出

## 需要回答的问题

库工程师先选 Vendor / SourceLibrary / Business IP，再判断：有哪些有效版本；针对某一个版本检查了什么；整个 IP 的各版本分别检查到什么程度；结果存在哪里。

旧页面把交付版本和有效版本放在总览中，却没有建立“版本 → 检查计划 → 运行 → 报告”的操作路径。当前页面分成三块：

1. **有效版本检查**：每行对应所选 IP 的一个 `effective_version.v1`。状态来自 `effective/index.json`；成员和父版本来自 `versions/rev_*.json`。每行展示和该版本完全一致的检查计划，执行后生成一个版本的 `report.xlsx`。
2. **整体 IP 检查**：要求所选 IP 的每个有效版本恰好有一个匹配计划，按版本依次运行；每个版本仍有自己的 JSON / HTML / Excel，另生成 `overall.xlsx` 与 `overall.json`，汇总执行状态和逐项检查。任何子运行失败时整体运行显示“部分失败”。
3. **供应商交付版本**：列出 source library 的 delivery 记录。V07、V08 表示供应商交付，不能直接等同于 rev_0001、rev_0002 或采纳状态。

## 计划如何匹配版本

检查计划来自工作台启动时的 `--plans` 目录。系统读取计划的 `target_revision`，对该有效版本 JSON 做 v3 Schema 校验，并要求完整内容与当前 work 目录中选中的版本记录一致。计划的事实和配对、插件与基线范围仍由计划显式指定；执行时沿用现有检查服务进行来源匹配。

`--plans` 和计划内部引用必须可信；相对路径按工作台启动时的当前目录解析。未绑定到具体 IP 的旧手动运行记录不会自动归入某个 IP。

单版本：如果匹配计划有多个，可选择一个运行；没有匹配计划显示“先准备检查计划”。整体检查：每版必须恰好一个计划；缺失或有歧义时不启动。当前示例只提供 rev_0002 的计划，因此不能把缺少 rev_0001 的情况标为整体检查完成。

## 输出与阅读边界

每次运行保存在 `--runs/run_<uuid>/`，历史不会被覆盖：

- 单版本：`check.json`、`report.html`、`report.xlsx`；详情可打开 HTML、下载文件或打开输出文件夹。
- 整体 IP：`overall.xlsx`、`overall.json` 和各版本子运行的链接。`overall.xlsx` 的“版本运行汇总”记录每版、计划、执行状态及计数；“逐项检查”列明检查 ID、文件范围、覆盖、结果和引用。逐版本子运行仍各自有完整的单版本 Excel。
- 报告生成或运行状态完成，只表示指定流程执行结束；不意味着所有文件、Corner 和检查规则都已覆盖或通过，也不意味着版本已采纳。检查只覆盖计划明确列出的事实和插件，当前证据链仍有可信性限制。
- 若电脑无法通过 `xdg-open` 启动文件管理器，页面显示可复制的输出路径，浏览器仍可进入输出记录和下载文件。

## 后续仍需完善

计划的生成和确认、缺失 Corner/文件覆盖核对、真实 RAW 来源认证、自动计划与后台进度、旧版两类 Excel 的字段及语义完整对齐、任意规则与跨库整体覆盖，仍未完成。整体 IP 汇总是已执行计划的结果清单，不是所有旧版检查能力的验收证明。
