# 路径式契约、查询与版本管理

本说明针对路径式新链路。旧 `data-query` 和旧版本命令使用历史契约；不要把同名旧索引直接当成路径式索引。

## 契约与配置

权威来源是每库 Delivery、Formal 和不可变 Effective JSON；`file_index.json` 是从三者构建的可重建索引。对应 Schema 分别为 `delivery_minimal`、`formal_path`、`effective_path` 和 `file_index_path`。FileFacts 和 CheckResult 有各自的 path Schema。时间点以 UTC 字符串保存，`version_date` 是日期，不是时间点。

新工作目录根下的 `path_sources.json` 同时保存 RAW / NL 根目录、NL 版本及各库配置，例如：

```json
{
  "raw_root": "/path/to/RAW",
  "nl_root": "/path/to/NL2.5.3",
  "nl_version": "NL2.5.3",
  "libraries": {
    "SRAM22": {
      "library_name": {
        "version_registration_times": {"V01": "2026-01-01T12:00:00Z"},
        "excluded_versions": []
      }
    }
  }
}
```

版本名日期决定日期组。同日带日期的版本用用户登记时间或已归档目录修改时间区分。无日期版本优先使用登记时间，其次目录修改时间，最后按自然版本顺序。为兼容旧工作目录，缺少新配置时暂时读取 `scan_sources.json` 的登记时间；新配置中同库设置优先。`inventory-roots` 未显式提供根目录时读取新配置，显式 CLI 参数优先。工作台保存来源时保留其他库配置。

工作台的一键同步与 CLI `refresh` 读取 `path_sources.json` 中的 `update_raw`、`update_formal`、`auto_effective` 和 `update_index`。CLI 可用 `--raw/--no-raw`、`--formal/--no-formal`、`--auto-effective/--no-auto-effective` 和 `--index/--no-index` 覆盖本次运行。关闭自动推进后，已启用的来源和索引阶段仍照常执行。单独执行 `refresh-effective` 或工作台「推进 L2」属于显式操作。

同步历史按供应商、库及来源记录观察时间，Formal 进一步按 NL 阶段区分。RAW 增量复用与完整核验分别显示。L3 逐库记录失败原因，CLI 有任何库刷新失败时返回退出码 1。总览和库工作台的 JSON 清单都先筛选，再按每页 100 项分页。

`update_raw`、`update_formal`、`update_index`、`auto_effective` 默认为 true，CLI 与 Web 使用相同配置。CLI 使用 `--raw/--no-raw`、`--formal/--no-formal`、`--index/--no-index` 和 `--auto-effective/--no-auto-effective` 临时覆盖（原 `--skip-*` 仍可用）。Web 保存当前选择，后续 CLI 也读取它。

## 查询与检查输入

`PathDataQuery.index` 校验索引新鲜度；`get_check_context(vendor, library, revision, baseline=None)` 返回该版本实际成员、路径、来源和基线（默认上一有效版本）。不根据 RAW 包自行补充成员。`path-check-context` 在 CLI 暴露相同查询，新检查入口从该查询取得成员。它只支持单 SourceLibrary，不隐含跨库 BusinessIP。

## Effective 操作

`minimal-effective-init` 使用 Formal 的匹配链接初始化；默认全部匹配，`--include VIEW=path` 可明确限制范围。

`path-delivery-preview` 仅用指定交付中与当前有效集 View 和相对路径相同的文件替换既有成员；未出现的成员继承，新增路径不自动纳入。返回的 `operations` 可存为 JSON 供 `path-effective-apply` 使用；`path-effective-preview` 也支持对明确 set/remove 操作预览。apply 必须提交预览得到的 `--expected-parent`，父版本变化会拒绝发布；相同成员集合不生成重复版本。原来的 `minimal-effective-update` 仍可直接更新，不具备预览后乐观并发保护。

`path-delivery-exclude/include` 更改配置，只影响后续候选使用；不删除交付，也不改写已发布版本。返回 `currently_used`，提醒当前有效集是否已使用该交付。`path-effective-restore` 以历史成员组合发布一个新版本，不覆写历史；恢复已排除来源的历史组合属于显式恢复。所有最新指针为相对软链接。

默认在扫描新交付时，若库已有 Effective，则按确认的交付顺序自动发布：只替换当前有效集里相同 View 和相对路径且来源更旧的成员，其他成员继承；不推断删除、不扩张管理范围、不把检查结果当作发布条件。没有初始 Effective 的库不会凭 RAW 自动确定管理范围，需先从 Formal 选择初始化。排除的交付不会参与自动发布；已跳过的交付重新包含后需要显式预览应用。

每库 `.auto_effective_state.json` 保存新登记但尚未处理的版本；顺序未确认、关闭自动发布或未启用索引刷新时保留待处理状态。下次 RAW 更新且打开自动发布、索引刷新时重试。处理完成后出队，重复扫描不会重复生成版本，也不会因恢复历史版本而重放旧交付。扫描路径清单不做 SHA-256；同路径文件原地修改不能单凭 Delivery 判断。目录创建时间与历史不同时单独提示，不冒称文件内容变化。

## 旧身份迁移

`path-migrate-library --source OLD_WORK --destination NEW_WORK --vendor V --library L` 在独立工作目录转换简化 Delivery、Formal、有效版本，使用旧映射还原准确文件路径，生成新的索引和最新软链接，不把旧身份 sidecar 写入新目录。未知或不唯一的引用、无链接目标、跨库有效成员、重复版本及不连续历史会阻止该库迁移；已有目标库不覆盖。迁移后的正式链接来自归档记录，不能证明现场链接或文件内容未改变。

迁移只处理上述契约；旧工作目录外的旧检查结果、历史报告、设计样本和 `workbench_runs` 不会自动转换或清除。需要清理时应分别确认其用途。新索引当前仍通过重建比较完整校验，并非增量性能方案。

## 同步状态与报告刷新

L2 初始化或演化失败时记录受影响的库和原因，并将失败计入 CLI 退出状态、Web 后台任务和同步批次。即使 L3 成功，整体状态仍保留 L2 的失败。指定 `--no-auto-init` 时，尚无有效版本的单轨库和多轨业务 IP 都跳过首版初始化。

增量检查将已保存结果与当前解析范围和 Liberty 抽样策略对照。策略变化标为 `STALE_TOOLING`，使用 `check-pending --include-outdated` 重检。采纳或采纳回退后，两类 Excel 在再次生成或下载时更新，原有检查 JSON 和事实证据可继续复用。
