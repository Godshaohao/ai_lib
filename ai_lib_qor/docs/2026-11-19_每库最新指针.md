# 每库最新指针

每个 `work/libraries/<vendor>/<library>/` 下有两个独立的可重建 JSON：

- `latest_delivery.json`：该库**已登记交付记录**中可确认的最新一条。`latest.file` 是同库 Delivery 文件名，`delivery_id` 是记录内部身份，`version` 是供应商版本；不说明 RAW 文件内容是否变化或历史是否仍可重现。
- `latest_effective.json`：`sets` 逐个列出该库有效集的最新计算 Revision 和文件名。它不记录、改变或替代人工采纳状态；采纳状态继续由原 `effective_<set>_index.json` 和事件日志维护。

若有一份交付，最新只指**唯一已登记记录**；多个交付需所有交付有已确认顺序，或在 `scan_sources.json` 中针对该库明确配置 `"order_rule": {"type":"VERSION_DATE_PREFIX", "confirmed":true}`，且版本名可按 YYYYMMDD 前缀严格排序、日期无歧义。文件编号、默认发现排序和扫描时间不能自行证明业务顺序。顺序不明时 `latest=null`、`status=ORDER_UNCONFIRMED`。

有效版本通过校验完整父版本链、采纳日志，以及索引（如果存在）与历史的一致性来确定；无有效集时 `NO_EFFECTIVE_VERSION`，记录损坏、父链不连续或索引不一致时对应有效集 `UNAVAILABLE`。v1 与纯 v2 历史分别支持，混合历史目前不支持；v2 权威发布和检查工作台迁移仍需完成。计算结果可以重建，不是修改历史记录。

正常交付自动登记、人工登记和扁平结构下的版本索引更新均会在库锁内重建两个指针；失败扫描也会创建空指针。也可以不扫描来源，显式重建已有库或所有已配置/已存在库：

```bash
PYTHONPATH=src:../src python3 -m ai_lib_qor latest-refresh --work work
PYTHONPATH=src:../src python3 -m ai_lib_qor latest-refresh --work work --vendor SRAM22 --library sram22_256x16m8w8
```

两个文件分别独立原子替换，不是跨文件事务；如中途故障，可重新运行 `latest-refresh`。运行过程中新增的不可变 Delivery/Revision 不会因为指针失败被回滚；要检查命令返回和指针状态，必要时重建。`latest` 指针表示已登记/已计算数据，不证明文件内容检查通过、Formal 覆盖完整或已采纳。

对 `effective.simple.v2`，独立 `effective-build` / `effective-formal-init` 不指定 `--work` 时只输出指定 JSON，不更新库指针。指定 `--work` 且输出为对应库中的 `effective_<set>_<序号>.json` 时，会验证已保存 Delivery、父版本和现有索引，持库锁写入 v2 版本并重建该有效集的索引及两个库级指针；旧 v1 与 v2 混合历史仍不支持。历史/索引不一致、交付无法定位或目标已存在时拒绝发布。成功计算不会自动采纳。
