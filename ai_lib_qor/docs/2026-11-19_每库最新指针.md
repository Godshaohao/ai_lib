# 每库最新软链接

每个库的最新入口是**相对符号链接**，读取链接会打开同目录中原有 JSON；链接本身不保存 JSON 副本：

```text
work/libraries/<vendor>/<library>/
├── delivery_005.json
├── latest_delivery.json -> delivery_005.json
├── effective_<set>_002.json
├── latest_effective.json -> effective_<set>_002.json
├── formal_NL2.5.3_001.json
└── latest_formal_NL2.5.3.json -> formal_NL2.5.3_001.json
```

只有一个有效集时提供 `latest_effective.json`。如果同一库有多个有效集，每个有效集分别使用 `latest_effective_<set>.json`；此时不创建有歧义的 `latest_effective.json`。链接指向最新计算版本，不代表已采纳；采纳状态仍由现有索引和事件日志管理。

只有唯一已登记交付，或所有交付的业务顺序已经确认，才创建 `latest_delivery.json`。对于日期前缀格式，可在 `scan_sources.json` 中对应库的配置里明确增加 `"order_rule": {"type":"VERSION_DATE_PREFIX", "confirmed":true}`；仅当已确认日期前缀确实代表业务顺序且所有日期无歧义时使用。文件编号、默认发现顺序和扫描时间不是确认依据。没有可确认目标、数据损坏、有效版本链/索引不一致时，不创建对应链接，也会移除本程序管理的旧链接，防止保留过时目标。`latest-refresh` 的输出会显示状态及库身份。

交付登记、扁平库下有效版本发布和显式 `--work` 的 v2 发布会自动更新链接；用户也可基于已保存记录重建，**不会扫描 RAW 或 Formal**：

```bash
PYTHONPATH=src:../src python3 -m ai_lib_qor latest-refresh --work work
PYTHONPATH=src:../src python3 -m ai_lib_qor latest-refresh --work work --vendor SRAM22 --library sram22_256x16m8w8
```

自动更新在库锁内完成，每个链接通过临时软链接与 `os.replace` 原子替换；多个链接之间不构成跨文件事务。之前生成的两类普通 JSON 指针，只在 Schema 和库身份核对通过时安全转换/删除；其他普通文件和非本程序管理的软链接不会被覆盖。链接目标始终是同库中的相对文件名，不能越过库目录。

验证 `ls -l` 或 `readlink` 可以看到链接目标。指针不证明内容相同、Formal 覆盖完整或质量检查通过；v1/v2 混合有效版本历史仍不能重建为有效链接。

每个 Formal NL 阶段分别生成 `latest_formal_<NL>.json`，例如 `latest_formal_NL2.5.3.json -> formal_NL2.5.3_001.json`。只有快照历史具有唯一完整父子链时才建立链接；缺失、分叉、循环或损坏时不猜测。链接指向最新已记录快照，快照的 `coverage=PARTIAL` 仍然代表范围不完整。Formal 同步发布或复用快照后在库锁内自动更新；链接更新失败会如实报告快照已保存但同步部分失败。
