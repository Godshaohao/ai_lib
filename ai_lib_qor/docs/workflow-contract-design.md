# 库更新到报告：流程与契约（实施设计）

状态：设计；除现有 v3 契约外，本文新增的记录和自动编排尚未全部实现。

| 步骤 / 界面操作 | 输入 | 输出 / 状态 | 关键约束 |
|---|---|---|---|
| 扫描库 | 明确配置的库根目录、前次成功观察 | scan_observation.v1：范围、时间、状态、文件路径和 SHA-256、变化；失败项 | 不写 RAW；扫描失败不得表示无变化；不可达文件不能声明删除 |
| 确认登记 | 扫描记录、供应商交付元数据、确认后的文件位映射 | 既有 delivery_record.v1 | 新增或修改只是观察，必须确认归属；未确认文件不得静默纳入 |
| 构建候选 | 交付、明确父版本 | 既有 effective_version.v1 | 默认最新计算版本；界面显示父版本及当前采纳版本；写入时校验最新版本未改变；删除必须显式声明 |
| 准备事实 | 目标和基线成员、来源文件、解析器及配置 | 既有 file_facts.v1；独立 provenance 记录内容哈希和配置 | 校验登记时的摘要与当前摘要；不一致停止并要求重新登记，不能覆盖旧事实 |
| 准备计划 | 明确目标、基线、规则、事实、配对 | 检查计划 JSON | 默认基线为父版本，可显式选择历史版本；初始版本无基线；配对歧义阻塞 |
| 检查 | 固化计划及事实 | 既有 check_result.v1 | 检查依赖目标的完整成员集合；显示覆盖、失败和未执行；执行完成不代表通过 |
| 输出 | 明确的检查记录 | 单版本 Excel / 整体 IP Excel 和汇总清单 | 整体列明每个 revision 的 run、基线、规则、时间、缺失及失败；不得悄悄混用不兼容结果 |

## 扫描记录拟议字段
`schema_version`, `scan_id`, `vendor_id`, `source_library_id`, `root`, `started_at`, `finished_at`, `status`（COMPLETE/PARTIAL/FAILED）, `files[]`（相对路径、大小、sha256）、`errors[]`, `previous_scan_id`。变化比较只对两次成功覆盖的路径进行；权限错误、符号链接、读取中修改应标记不完整。

## 复用判定
- 事实复用键：文件内容 SHA-256、parser 名称和版本、配置哈希、事实契约版本及必要的来源身份。解析前后核对摘要，证据与对应来源身份绑定。
- 检查复用键：目标与基线记录身份、依赖事实身份、规则与插件版本及配置、检查契约版本。任一依赖改变只重新运行受影响检查；例如 LEF 变化时与之配对的所有 Liberty 检查均失效。
- 报告复用：引用具体 CheckResult，报告模板变更只重渲染；不重新解析。
- RAW 原地修改：保留旧记录及证据，将来源标记为已变化；禁止把该路径的新内容作为旧交付的内容。须显式登记新交付或修订，历史内容若无快照则标记不可重现。

## 界面与动作
库首页显示上次成功扫描时间、扫描范围、状态及新交付候选；提供“扫描全部已配置库”“扫描此库”。扫描结果提供“确认登记”，未解析文件列出原因。版本时间线区分本次交付文件数与有效成员数，提供“准备并检查”，展示准备事实、计划、执行、报告各阶段及阻塞项。已有结果提供查看和强制重检。整体报告先显示各版本被选中的结果及可复用/缺失/失效状态，提供“补齐检查并生成”和“仅汇总现有结果”。

## 整体报告选取
用户选择 revision 集合、统一规则配置及基线策略；逐版本展示实际基线及候选 run。仅复用键完全匹配且输入仍可验证的结果可自动选取；多个匹配按完成时间和 run ID 确定排序，并显示所选 ID。用户可显式改选兼容记录。缺失、失效、未执行及检查失败分别展示；仅汇总时绝不自动执行。若用户选择补齐，单版本失败不阻止汇总，但运行错误须记录，汇总不得暗示通过。
