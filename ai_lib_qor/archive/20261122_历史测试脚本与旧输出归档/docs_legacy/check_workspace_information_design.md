# 工作台信息设计：M1 实施记录

## 入口与范围

- 不指定 IP 时进入全局库更新；扫描状态来自扫描记录，只有大小与修改时间，不证明内容一致。
- 指定 Vendor、源库和 IP 时进入总览。最新计算与当前采纳来自 EffectiveIndex；所选成员来自 EffectiveVersion。
- 文件与 Macro 页面以所选版本和默认父版本（或明确选择的更早基线）的完整成员做并集。无基线时不计算来源变化；基线文件缺失显示不可读取。不同于交付文件出现历史。
- 来源解析仅使用已有 DeliveryRecord / FormalSnapshot 的完整引用和 file_key；缺失、重复或未加载的跨库来源不猜测。所选公共正式快照只在有效成员的文件位上对照；来源一致不证明内容一致。
- 历史 CheckResult 必须通过 schema 和一致性校验，并与已关联 owner、目标版本、基线和记录来源匹配；输入计划中的版本文件与选择的版本内容必须相同。显示的是历史记录，输入新鲜度未验证，不作为缓存或验收结论。Macro/Pin 的变化只来自该记录的 object_changes；逐条质量规则的结果及覆盖单独展示。
- 旧文件出现历史、交付清单对照、正式快照、运行历史与输出目录保留；运行入口集中在检查与验收页面。

## 仍未实现

- 自动计划、事实/检查结果复用有效性判断、历史检查的只读整体汇总、首次 IP 建档及跨库目录完整加载。当前整体 IP 按钮仍会按已有计划逐版执行。
- 未从源文件自动生成缺失的 Macro 变化；空记录、未支持的 PG/几何/时序等不能推断为无差异或通过。
- 适配浏览器和可访问性需要实际浏览器验收，测试客户端不会替代视觉验收。

## 库与 IP 的连续工作台

- 工程师先在来源总览选择 Vendor / SourceLibrary；库视角展示交付文件出现历史，不能把“最新交付文件”等同当前 IP 的有效文件。
- 库页与 IP 页共用工作台顶部、Vendor / 源库 / IP 侧栏，以及“库文件与交付 / IP”视角切换。库级数据由 `library_model` 读取已有交付和扫描；IP 视角由 `load_catalog` 读取有效索引和版本。
- 库页点击 IP 进入该 IP 总览；IP 页的面包屑和“库文件与交付”可返回原库。已经选择 IP 版本时，同一 IP 的视角入口保留当前 revision；切换其他 IP 时不推断其版本。
- 没有已登记 IP 时仍可浏览库，切换条显示“尚无已登记 IP”；不凭来源名称猜测业务 IP。历史“待确认交付”失效锚点已移除，旧交付和文件查询入口仍可访问。
- 关联关系以当前可读取的有效版本索引为依据；未建立索引的业务归属及跨库关系不能仅从该侧栏证明。
