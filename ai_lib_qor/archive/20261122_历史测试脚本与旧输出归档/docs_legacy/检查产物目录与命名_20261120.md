# 检查产物目录与命名

## v3 索引检查的新产物

单版本和整体 IP 的新检查结果写到所属库：

```text
work/libraries/<vendor>/<library>/
  delivery_001.json
  formal_<NL>_001.json
  effective_<set>_001.json
  file_index.json
  facts_<来源及解析键24位>_<事实内容校验24位>.json
  check_run_<32位运行ID>.json
  report_run_<32位运行ID>.xlsx
  report_run_<32位运行ID>.html
  overall_run_<32位运行ID>.json
  overall_run_<32位运行ID>.xlsx
  runs.jsonl
```

`facts_` 是按来源范围、交付、文件身份、所选文件内容、解析器版本生成的可复用事实；后两段是缓存键和事实内容校验值，不是交付顺序。`check_run_*` 是单版本 CheckResult；`report_run_*` 是同次检查报告。`overall_run_*` 是整体 IP 汇总，每个版本仍分别生成自己的 check 和 report。运行 ID 是唯一标识，不代表版本顺序；版本、基线与运行先后查 `runs.jsonl` / Effective 历史。

每次运行在 `runs.jsonl` 追加 RUNNING 和最终状态；其中包含 set、目标、基线、检查配置和文件名。失败不会伪造 PASS。相同库的策略审计记录也可在该日志中，以 `kind` 区别；采纳记录仍保留在 `effective_*_acceptance.jsonl`。新 v3 检查不另建 input_plan.json 或 run 子目录。

## 历史兼容和范围

历史 `runs/run_<id>/...` 保持原位，Web 通过旧 URL 继续查看和下载；不自动移动或删除。新 v3 检查的 Web URL 仍使用 `/runs/<id>/...`，服务端映射到实际库目录，下载文件名采用实际规范名称。扫描历史和正式库观察暂仍在现有 runs 根目录；旧的非 v3 计划执行入口暂保持旧输出位置，不应误称已迁移。

运行时 `--runs` 仍用于旧产物的读取和其他兼容入口，不是新 v3 检查产物目录。运行数据和报告不写入 RAW 或 Formal 来源目录。
