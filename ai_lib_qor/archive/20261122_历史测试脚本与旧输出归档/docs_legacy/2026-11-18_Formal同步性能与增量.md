# Formal NL 同步：路径索引与增量发布

状态：已实现，以下测量为本机临时模拟数据，不代表真实网络存储性能或生产验收。

## 算法

1. 对整个 NL 目录做一次盘点，获取每条链接的路径、目标和状态；同时将已登记 RAW 文件按实际绝对路径建立哈希表，同一路径的多个候选保留，不强行选择。
2. 唯一匹配的链接按 `(NL, Vendor, 来源库)` 分组；不能唯一匹配的保留在观察记录。范围配置和跨供应商重复引用仍需校验。
3. 每组复用同一份目录盘点和来源路径索引构造候选；每条链接在发布前再次解析并与观察结果比对。未解析文件位不伪造来源引用，目录链接、范围不完整和失效链接不能证明完整覆盖。
4. 与该库上一份快照比较覆盖状态、范围、文件位、链接、目标及来源引用。全部相同则复用快照 ID；不同则追加新快照并保留父链。库最后一个已知链接消失时，提示本次无唯一归属链接并保留旧历史，不自动推断删除。

令 `N` 为 NL 观察文件数、`M` 为已登记 RAW 文件数、`n_i` 为第 `i` 库的链接数；不计目录系统调用、JSON 校验与历史读取时，建索引与分组平均约为 `O(N + M)`，各库排序约为 `O(Σ n_i log n_i)`，空间约为 `O(N + M)`。哈希表是路径查找结构，不是文件内容哈希。历史 JSON 的读取和校验成本另计，历史较长时不保证常数时间。文件系统访问耗时随目录结构和存储类型变化。

这是**增量发布**：每次仍完整观察当前 NL 并复核已归属的链接，且每库仍构造候选后才能判断是否复用；并非只扫描变化目录，也不是内容增量对比。`size + mtime` 或链接目标不证明文件内容相同；本流程不计算文件内容 SHA-256。内容原地改写、观察后的并发变化、网络文件系统缓存都不能由此完全排除。当前盘点函数的默认上限为 100,000 个文件。

## 可重现测量

```bash
cd ai_lib_qor
PYTHONPATH="$PWD/src:$PWD/../src${PYTHONPATH:+:$PYTHONPATH}" \
  python3 scripts/benchmark_formal_sync.py --libraries 100 --files-per-library 100
```

脚本在临时目录生成独立 RAW、NL 和 work，测量首轮、不变重跑以及一个库中的一个链接变更，验证每轮只调用一次目录遍历和预期快照动作。2026-11-18 本机一次运行结果：

| 场景 | 库 / 链接 | 耗时 | 遍历 NL | 快照结果 |
|---|---:|---:|---:|---|
| 首轮 | 100 / 10,000 | 3.408 秒 | 1 次 | 新建 100 |
| 无变化 | 100 / 10,000 | 4.188 秒 | 1 次 | 复用 100 |
| 一个链接目标变化 | 100 / 10,000 | 4.264 秒 | 1 次 | 新建 1、复用 99 |

计时不包含模拟数据生成；包含盘点、已登记来源路径解析、历史读取、Schema 验证和快照处理。此结果不能直接外推至生产机器、NFS 或长期历史累积。重复运行会受到缓存和其他进程影响，也没有同机旧版本速度对照，不据此宣称倍数提升。
