# 扁平库目录与 JSON 命名

新记录统一位于 `work/libraries/<vendor_id>/<source_library_id>/`；Vendor / 来源库 ID 使用字母、数字、点、下划线、连字符，不允许路径穿越或目录符号链接。旧目录保留并由 Repository 兼容读取，不自动迁移。

| 文件名 | 含义与序号规则 |
|---|---|
| `delivery_001.json` | 按本库已使用的文件名递增分配，超过 999 自动扩位。JSON 内 `delivery_id` 才是交付身份，`supplier_version` 才是版本标签；文件名序号不是供应商交付顺序。 |
| `evidence_delivery_001.json` | 上述 v1 交付的扫描证据，含大小、mtime、分类依据；仍需保存以区分文件名候选，不能将它当第二份交付。 |
| `formal_NL2.5.3_001.json` | 按本库、同一 NL 已有文件名递增分配；快照身份、父链和范围以 JSON 为准。不同 NL 独立编号。 |
| `effective_<set_id>_001.json` | 有效集的 `rev_0001`，成员为全集；序号表示该有效集的计算 Rev，不表示采纳。 |
| `effective_<set_id>_index.json` | 可重建索引，分别保存最新计算与当前采纳。 |
| `effective_<set_id>_acceptance.jsonl` | 人工采纳/回退事件，追加写入。 |

新文件名分配在同一库的锁内进行，历史不覆盖；ID 仍保存在各自 JSON，不根据文件名推断来源或版本时序。交付 / 正式快照可能因 v1 契约继续有旁证和观察记录。`runs/` 保存扫描和操作记录，不把输出归档成 RAW 文件副本。

配置示例：[RAW 来源](../examples/flat_layout/scan_sources.example.json)、[Formal 来源](../examples/flat_layout/formal_sources.example.json)。JSON 没有注释语法，因此用顶层 `_comment` 和 `_naming` 描述；程序只消费 `sources`。这些字段仅说明固定规则，不是可自定义文件名模板。

有效集 CLI 使用逻辑前缀作为 `--effective-dir`：例如 `--effective-dir /path/work/libraries/SRAM22/sram22_256x16m8w8/effective_sram22_256x16m8w8 --set-id sram22_256x16m8w8`。该路径是文件名前缀，不创建同名文件夹；交付必须先在同一 work 中登记。跨库身份须明确确认；Form​al 的 `PARTIAL` 不可冒充完整基线。旧有效集仍使用原 `effective/versions/` 目录。

当前 v1 快照中的路径匹配与文件位确认仍未完全分离；文件名候选不是人工确认，也不代表内容一致。
