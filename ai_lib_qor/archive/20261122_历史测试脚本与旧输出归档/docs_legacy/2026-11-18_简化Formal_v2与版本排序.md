# 简化 Formal v2 与版本排序

状态：本文记录 v2 简化视图的历史设计；当前新同步使用 `formal_snapshot.v2`，简化查询输出 `formal.simple.v3` 并保留软链接原文，见 [Formal 链接目标记录](2026-11-18_Formal链接目标记录.md)。既有 v1 历史未迁移；简化查询不是权威快照，已有 Web / Excel / 有效版本引擎未全部切换。

RAW 保持 `raw.simple.v1`：`schema`、短 `delivery_id`、`context`、`views`。DOC、OTHER 等从已归档 v1 文件列表派生，文件都应保留；没有新增来源目录扫描或内容解析。

Formal 导出为 `formal.simple.v2`：保留 `schema`、`snapshot_id`、`context`、`views`。已关联同库文件默认只保存 `raw_version` 和 `raw_path`；若该 Vendor / 库中相同版本名存在多条交付，增加 `delivery` 消歧。跨库时额外保留不同的 `vendor` / `library`。非 `CONTRACT_REFERENCE` 的匹配方式保留 `match_basis`；未关联项保留 `resolved_path`，非空 `unassigned` 保留。匹配的绝对路径可以经 RAW 上下文和相对路径重建，但无法关联的目标不能丢。

v2 简化文件不包含 `coverage`；这表示**未在导出视图中声明完整性**，不表示 NL 范围完整。原 v1 快照仍可核验，本次样本为 `PARTIAL`。简单格式不能自行证明完全基线或采纳；`compare_formal()` 对 v2 输出 `formal_coverage=UNDECLARED`。若缺少可唯一匹配的 RAW 版本 / 交付，结果为 `UNKNOWN`；比较只描述已记录来源，不证明字节一致。

`scan_sources.json` 来源可选 `order_rule: {"type":"VERSION_DATE_PREFIX","confirmed":true}`，只有人工确认供应商始终使用 `YYYYMMDD` 或 `YYYYMMDD_<后缀>` 后才启用。程序校验真实日历日期，存在相同日期、多交付同日或任一不符合的标签时，返回 `ORDER_UNCONFIRMED`，不按接收时间、文件名或猜测的后缀补排序。示例配置默认 `confirmed=false`。此规则目前接入 `LibraryDataQuery` 和纯 `build_history`；旧矩阵、Excel 和版本构建流程尚未统一迁入，不可称为全系统排序已统一。

用 `data-query --kind simple-raw`、`--kind simple-formal` 从已登记 v1 JSON 导出。`build_effective` 要求调用者明确提供交付顺序和参与 View；仅按同库、同 View、同相对路径更新，不因交付缺文件而删除，不自动认定改名或采纳。`compare_formal` 的 v2 版本关联需要提供相关 RAW 记录；不唯一时返回 UNKNOWN。
