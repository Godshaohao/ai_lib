# 来源库集中存储与 Formal NL 快照

状态：已实现；模拟测试和本地公开样本只读试验，不等于生产验收。

```text
work/vendors/<vendor>/libraries/<library>/
├── deliveries/<delivery_id>/delivery.json   # RAW 登记
├── formal_nl/<NL>/snapshots/<snapshot_id>/snapshot.json
└── ips/<ip>/effective/                       # 有效版本及采纳
```

同库集中保存业务记录，不复制或改写外部 RAW 和 Formal NL 文件。原 `work/formal_nl/<NL>/snapshots/` 的快照保持原位并可读取，不自动转存、改写或继承其父链。每个 NL、Vendor、来源库有独立历史；快照 ID 随机且在 NL 范围内使用 UUID。结果文件是 v3 FormalSnapshot，没有新增 Schema 字段。引用不含 Vendor，因此相同来源库／交付／文件 ID 在多个 Vendor 中重复时，禁止发布有歧义的匹配引用。

一次 NL 同步根据各交付记录的原始绝对路径，盘点并分组；对于唯一归库的链接，每库单独创建或复用快照。每条路径再次核实目标；每库的文件位冲突阻止该库发布。没有文件位的链接可以写入部分快照，但按当前契约标为 `UNMATCHED`、空 `source_ref`；观察记录仍可说明其唯一路径来源。无法唯一归库的链接只保留在观察记录。断链、未登记目标、目录链接及错误不会证明不存在或删除。当前分库快照统一为 `PARTIAL`，不会声明完整范围。

`formal_sources.json` 可选用 `libraries` 限定可发布的来源库，例如：

```json
{"sources":[{"formal_nl_id":"NL2.5.3","root":"/实际/NL目录",
  "libraries":[{"vendor_id":"IHP","source_library_id":"sg13g2_stdcell"}]}]}
```

未配置 `libraries` 时允许全部已登记库；空列表表示不发布任何库。范围之外但能唯一识别的链接在观察中标记 `OUT_OF_SCOPE`，不写快照。`scan_sources.json` 继续负责 RAW 根目录、版本路径和显式文件映射，配置方法参见 `07_CLI与工作台共同数据流.md`。

目前自动推断的文件位仍可能标为 `RESOLVED`，尚未与人工确认彻底分离。因此快照的 RAW 引用证明的是路径与当前已登记文件位的一致关系，不能证明该业务文件位已人工确认、文件内容不变，或 IP 归属正确。人工仍需确认来源根和身份、可复用的文件身份规则，以及冲突、缺失、跨库歧义；若需要完整替换或删除，还需提供交付范围和顺序依据。完整的跨版本规则配置和人工确认流转尚未实现，不应把候选当成已确认。

每次同步只盘点一次 NL 根目录，按唯一目标路径建立索引并在各库快照构建时复用；提交前仍逐条复核链接目标。同一个库没有变化时复用已有快照；发生变化时只为该库追加快照。测试方法和规模、复杂度与限制见 [Formal 同步性能与增量规则](2026-11-18_Formal同步性能与增量.md)。快速观察不计算文件内容 SHA-256，不能证明同大小、同时间戳的文件内容未变。
