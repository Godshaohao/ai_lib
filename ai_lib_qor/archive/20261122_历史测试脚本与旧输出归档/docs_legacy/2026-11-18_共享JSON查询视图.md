# RAW、文件历史、有效版本和 Formal 的共享查询视图

状态：已有 v1 权威 JSON 不变；本次实现内存派生视图和 CLI / Web JSON 查询。文中 `raw_view.v1` 等是查询结果标识，不是新的持久化权威 Schema。附件中 `raw.v2`、`effective.v2`、`formal.v2` 的权威持久化切换尚未实施；现有 Excel 和 HTML 页面尚未全部接到这些新接口。

`LibraryDataQuery` 通过 `SourceRepository` 和 Catalog 读取已保存 Delivery、FormalSnapshot、EffectiveVersion，不扫描 RAW 或 Formal。一次实例化构造内存索引；不写 `file_history.json` 或其他权威副本。

| 接口 | 结果 |
|---|---|
| `get_raw_files(vendor, library, version, view=None, delivery_id=None)` | `context` 与 `views`；常规 View 为路径数组，LIBERTY 根据路径中的 NLDM/CCS/ECSM 分组，DOC 根据后缀分组；无法判定子类为 UNKNOWN。相同版本多次交付必须提供 `delivery_id`。 |
| `get_file_history(vendor, library, view, path)` | 当前路径的每次出现及来源；证据不支持可比较顺序时为 `ORDER_UNCONFIRMED`，`latest` / `previous` 均为空。相同路径不自动证明相同逻辑文件位，改名不自动关联。 |
| `get_history_index(vendor, library)` | View → 路径 → 出现记录的嵌套字典，内容为可重建查询结果。 |
| `get_effective_files(vendor, library, owner, revision, view=None)` | View → 路径 → 来源对象；保留 Vendor、库、交付 ID、文件 ID 和来源引用。文件位找不到时在 `unresolved`，相同 View / 路径碰撞时报错，不覆盖。 |
| `get_formal_files(vendor, library, nl, snapshot_id, view=None)` | View → 正式路径 → RAW 引用、记录的目标和匹配状态；v1 缺少 source_ref 时可按已归档的目标路径文本唯一反查交付，标记 `ARCHIVED_PATH_TEXT`。这不是实时文件存在或字节一致证明，也不改变原始 `UNMATCHED` 或未知文件位。无法唯一归属时保留目标，老全局快照置于 `unassigned`，不会猜 Vendor。 |
| `compare_effective(vendor, library, owner, rev_a, rev_b)` | 对比完整成员来源引用，结果是 `SOURCE_RELATIONSHIP_ONLY`，不证明文件内容改变。 |

`.spice` / `.sp` 在查询视图中按路径扩展名显示为 SPICE，即使旧记录标为 CDL；这只是名称提示，不修改原记录，也不证明文件内容格式。其他原始 View 优先保留记录值。

## CLI / Web

```bash
python3 -m ai_lib_qor data-query --kind raw --work /path/to/work \
  --vendor SRAM22 --library sram22_256x16m8w8 --version 20261024_de0a9a7

python3 -m ai_lib_qor data-query --kind history-index --work /path/to/work \
  --vendor SRAM22 --library sram22_256x16m8w8
```

其余 kind 为 `history`、`effective`、`formal`、`compare`，参数参见 `data-query --help`。Web `GET /api/library-data` 调用相同 `query_data`，参数使用下划线，例如 `other_revision`。查询是只读的，输出重定向到文件时由调用方决定保存位置；保存的结果是快照式派生视图，不参与业务权威计算。

可使用上述查询命令针对本地隔离样本生成 RAW、文件历史、有效版本、Formal 和来源差异的示例 JSON；模拟有效版本和采纳不代表生产决定。
