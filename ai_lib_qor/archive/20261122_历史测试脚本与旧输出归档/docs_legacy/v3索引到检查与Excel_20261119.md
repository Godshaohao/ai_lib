# v3 索引到 FileFacts、CheckResult 与 Excel

## 确认范围与依赖

真实库日期顺序由用户于 2026-11-19 确认：IHP `sg13g2_stdcell` 和三个 SRAM22 库优先按版本名中的有效 YYYYMMDD 前缀；版本没有日期时，按用户明确登记、带时区的交付时间排序。当前真实交付均有日期，无需回退。回退时间由 `delivery_registration_times` 按真实交付 ID 显式配置，`order_timezone` 指定比较时区；不能把扫描完成时间、自动填入的接收时间或目录时间假装成用户登记的交付时间。缺时间、非法日期、同一天中日期精度不足或排序冲突时保持未确认。IHP `RM_IHPSG13_1P_64x16_c2` 目前只有一份记录。

例如，以下片段放入 `scan_sources.json` 中对应库的来源配置：

```json
{
  "order_rule": {"type": "VERSION_DATE_PREFIX", "confirmed": true},
  "order_timezone": "Asia/Singapore",
  "delivery_registration_times": {"真实交付ID": "2026-11-19T09:30:00+08:00"}
}
```

日期仅确定到天；同一天的两个交付只要存在一个仅有日期的版本，就不猜测当天内部先后。不同版本没有日期但登记了可比较的时刻时，才可按时刻排序。完整的显式 `delivery_order_ids` 可指定最终顺序；配置了已确认的日期规则时，日期及用户登记时间优先于旧的 `delivery_orders` 数值。

五个真实库已从归档记录建立 v3 索引并刷新 latest 软链接。索引是来源投影，不证明 RAW 当前内容或完整质量。真实交付文件目前的身份多为 `CANDIDATE` 或 `UNKNOWN`；`SRAM22/sram22_256x16m8w8` 当前两个旧有效版本属于 `SOURCE_LIBRARY`，不是已确认的 BusinessIP。不能自动将候选身份或库归属转为已确认 IP，也不能据此生成可信的整体 IP 检查结果。

## 输入、输出与检查范围

`v3_checks.py` 首先确认已保存 v3 索引与归档记录一致，按显式有效集、Revision 和检查配置获取精确来源。检查配置例如：

```json
{
  "pin_pairs": [
    {"lef_path": "lef/core.lef", "liberty_path": "lib/core.lib"}
  ]
}
```

路径对由使用者根据实际对象确认；不凭名称自动认定配对。被选文件须有真实、唯一的 Delivery/file ID 和明确确认的文件身份。若来源存在归档时的 size/mtime，则检查时比较当前元信息；不匹配拒绝重现。没有保存元信息时，报告注明无法验证历史内容；元信息相同也不证明内容完全相同。只解析所选 LEF/Liberty，不批量哈希或解析整库。单次整体运行内可复用同一文件的事实；运行间不复用缓存。

每个 Revision 默认以其记录的父 Revision 为基线。初始版本没有基线，只做目标 LEF–Liberty 信号 Pin 对齐；后续比较所选 LEF 的 Macro SIZE 和 Pin，并检查目标版本 LEF–Liberty 信号 Pin 对齐。当前**不比较新旧 Liberty 内容**，不检查 GDS、Verilog、CDL、PG 或全部质量规则。整体报告按有效版本链顺序汇总同一次各子运行的 `check.json`；执行完成与质量 PASS 分离，报告不自动采纳版本。

单版本 `report.xlsx` 保留现有工作表，新增 `12-有效文件来源` 和 `13-版本来源对照`。后者来自 v3 索引，按 View + 路径描述所有有效文件的来源关系；文件改名时会显示新增和移除路径，已确认的逻辑文件关系另由逻辑历史查询提供。整体 `overall.xlsx` 同时列出“已检查文件”的内容差异与“按路径来源变化”，两者口径不同。每个子运行还保存 `input_plan.json`、`facts_*.json`、`check.json`、HTML 和状态；整体运行保存 `overall.json` 和 `overall.xlsx`。

## 命令与工作台

在 `ai_lib_qor` 目录，使用本项目 Python 依赖环境：

```bash
export PYTHONPATH="$PWD/src:$PWD/../src${PYTHONPATH:+:$PYTHONPATH}"
python3 -m ai_lib_qor run-v3-revision --work WORK --runs RUNS \
  --vendor VENDOR --library LIB --set-id SET --revision rev_0002 --profile PROFILE.json
python3 -m ai_lib_qor run-v3-ip --work WORK --runs RUNS \
  --vendor VENDOR --library LIB --set-id SET --profile PROFILE.json
```

整体命令默认检查该 BusinessIP 有效集的全部版本，可多次指定 `--revision` 选择部分版本，比较基线仍是各自父版本。单版本命令要求恰好一个 `--revision`。工作台计划目录中的 `v3_profile_*.json` 会显示在有效版本页面；可执行单版本或全版本，运行详情列出 CheckResult、Excel、HTML 和 FileFacts。以上检查配置不等同于人工采纳。
