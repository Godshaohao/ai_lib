01 / PURPOSE

这个系统解决什么问题？

供应商会反复交付不同视图的文件，正式库也可能指向不同批次。ai_lib_qor 的目标是把来源、有效版本和检查结果串起来，让人知道当前使用的文件是什么、它从哪里来、变化在哪里。

01 · 找到文件

按供应商、来源库和业务 IP 追踪每个文件的交付来源。

02 · 理解版本

区分最新交付、计算出的有效版本、已采纳版本与正式快照。

03 · 发现变化

比较文件和 Macro / Pin 事实，保留检查范围与结果。

02 / OBJECTS

核心对象如何关联？

这是业务对象关系图，不代表已经部署了多个服务。箭头表示提供、关联、引用或解析，具体含义标在连线上。

一次交付可以更新有效版本的一部分；其他成员可继续引用原来的正式快照。文件事实描述实际解析到的内容。

03 / FILES

同一个文件，现在处于哪个版本？

以下为文档中的合成示例：vendor_orion / lib_rtavfs / rtavfs。点击文件名查看该行解释。

文件最新交付次新交付最新计算 Rev 002已采纳 Rev 001正式 Snapshot 002
LEFV08V07V08 RAWV07 正式快照 001V07
Liberty / ttV08V07V08 RAWV07 正式快照 001V08
Liberty / ffV07未知V07 正式快照 001V07 正式快照 001V07
core.lef · V08 替换 V07

Rev 002 使用 V08 交付文件；已采纳 Rev 001 和正式快照 002 仍指向 V07。示例中 MAC_A 尺寸从 120 × 80 变为 124 × 80 μm，并新增信号 Pin C。

最新交付按文件分别判断；次新“未知”表示示例未提供更早历史。最新计算不等于已经采纳；正式快照是独立观察结果。

04 / DELIVERY

一次交付如何影响有效库？

V08 是增量交付，只包含 LEF 和 tt Liberty；没有交付 ff 并不代表删除 ff。

09.07 / 2026收到 V07

交付 LEF、tt 与 ff 三个文件。

09.09 — 09.11建立并采纳 Rev 001

以正式快照 001 的三个文件作为基线。

10.19 — 10.20V08 → Rev 002

替换 LEF 和 tt；ff 沿用快照 001。Rev 002 尚非已采纳版本。

10.21观察正式快照 002

正式库中 tt 已指向 V08，LEF 与 ff 仍指向 V07。

处理路径 · 拟议数据流

登记交付 / 正式快照→选择有效文件成员→解析与比较→记录结果与采纳

交付也可直接做预检查，无须先生成有效版本。文件来源变化与文件内容变化需要分别判断。

05 / MODULES

程序模块如何分工？

下列为拟议的逻辑模块和示意路径，当前页面未核实其已实现。点击每一项查看职责、输入和输出；它们不表示独立部署单元。

来源登记 sources/交付、文件与正式快照的入口

职责：扫描、识别并登记供应商交付和正式库链接，保留可追溯来源。

输入 → 输出：交付文件或正式库 → Delivery / Formal Snapshot 记录。

拟议路径：src/ai_lib_qor/sources/

文件解析 parsers/提取 LEF / Liberty 等文件事实

职责：复用适用的解析能力，记录 Macro、Pin 和解析覆盖范围。

输入 → 输出：具体来源文件 → File Facts；缺失解析内容保持未知。

拟议路径：src/ai_lib_qor/parsers/

有效版本 versions/选择成员与管理版本关系

职责：组合完整成员清单，记录父版本和来源变化。

输入 → 输出：上一个版本、交付和正式来源 → Effective Version。

拟议路径：src/ai_lib_qor/versions/

差异与检查 checks/比较文件、对象和视图

职责：对目标和基线做文件差异与可覆盖的质量检查。

输入 → 输出：来源引用、文件事实、规则 → Check Result；支持交付预检查。

拟议路径：src/ai_lib_qor/checks/

记录与索引 storage/保存版本索引、事件和检查记录

职责：读取与保存记录，区分最新计算版本和已采纳版本。

输入 → 输出：版本、采纳事件和结果 → 可追溯的持久化记录。并发与原子写策略待设计。

拟议路径：src/ai_lib_qor/storage/

报告呈现 reporting/让人查看来源、变化与结果

职责：将结构化结果组织为文件定位、版本差异和检查视图。

输入 → 输出：索引、版本、检查结果 → 人可读报告；展示形式待定。

拟议路径：src/ai_lib_qor/reporting/

D. 工程专有名词
English中文对象含义
LEF版图抽象文件Macro、SIZE、PIN、OBS、SITE 等物理接口事实
Liberty (.lib)时序库文件Library、Cell、Pin、时序/功耗模型等；本契约示例仅演示 Cell/Pin
Macro宏单元LEF 中定义的物理宏对象
Cell库单元Liberty 中的 cell 对象，不要与 LEF Macro 在存储层强制合成同一对象
Pin引脚需要区分方向、Signal/Power/Ground、PG Pin 和物理/逻辑接口
Corner工艺/电压/温度角及 RC 条件影响 Liberty 等文件的逻辑身份
View库视图LEF/Liberty/Verilog/CDL/SDC/UPF/CPF/SPEF/DB/GDS 等
QoR质量指标指标口径明确才称 QoR；不能把文件数变化简单称作 PPA 改善
RAW-first优先依据 RAW 文件历史不依赖正式 NL 也能定位和比较最新/次新交付文件
Delta差异指明是“采用来源差异”还是“解析内容差异”
关联关键：file_key 标识逻辑文件；source_ref 指向某次交付或某个正式快照中的具体文件。不要用最新交付或正式链接直接替代已采纳版本。
