# 设计验收场景（尚未实现自动化测试）

1. `work_root` 的 CLI、环境变量和 YAML 优先级正确；实际来源只读，路径穿越和危险根重叠被拒绝。
2. V07 包含 LEF/tt/ff，V08 增量只包含 LEF/tt：有效版本保留旧 ff；无证据不推断删除。
3. 交付预检查无需有效版本；相同 file_key 按实际出现和已确认顺序取最近与次近，而不是按版本字符串。
4. 固定 LEF 及关联 Liberty 正常匹配、方向不匹配、事实缺失及覆盖不足分别得到 PASS、FAIL、NOT_RUN、INCONCLUSIVE；不能扩大为整体 QoR 结论。
5. 两个合法插件贡献进入同一 v3 CheckResult；重复身份、来源冲突、不同目标、伪造 facts_refs、错误 Gate 依赖均不得通过。
6. 插件新增并注册后，只要贡献落在已支持的 v3 字段和通用接口内，不修改核心调度器；超出契约时先设计扩展，不丢失数据。
7. 变更检查参数只产生新 Run；人工采纳前 accepted 指针不随 Rev、PASS 或 Formal Snapshot 变化。
8. 已发布固定 ID 冲突拒绝覆盖；模拟发布中断、事件追加后索引失败、并发更新后能根据明确实现规则恢复。
9. 对同一 Run 生成 HTML 与 Excel，来源、文件变化和状态一致；缺失引用可见。
10. 对实际 v3 Schema 及跨记录关系进行完整校验；v5 `check_run.v1` 未验证字段映射前不得作为 v3 结果发布。
