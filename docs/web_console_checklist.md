# Web 控制台验收清单

Status: current

## 目标

Web 控制台只提供现有 `lib_guard` 事实的浏览和受控动作入口。Version Detail 仍然是唯一
版本审查投影，Web 不创建第二套 Catalog、Scan、Diff 或 Release 数据。

## 启动

在项目根目录执行：

```bash
python3 -m venv .venv-web
. .venv-web/bin/activate
python -m pip install -r requirements-web.txt
PYTHONPATH=src python -m lib_guard.web.app \
  --config work/single_library_smoke_20260805/lib_guard.yml
```

浏览器打开 `http://127.0.0.1:5000/`。

## 页面检查

- [ ] 顶层只有“库工作台 / 发布中心”两个工作域；库内可切换版本、分析与结果、设置与维护。
- [ ] 版本列表默认展开；选中版本只给一个由扫描/对比就绪状态决定的主操作，详情入口为次操作；切换库、版本或标签不提交写任务。
- [ ] 主操作在没有选中版本、动作被阻塞或已有任务运行时保持禁用；运行期间不允许重复提交。
- [ ] 分析结果显示扫描状态、对比结果和实际记录的对比基准；不得把相邻版本建议显示成实际对比基准。
- [ ] 发布中心内“单库发布 / 多库组合 / 发布阶段”互斥切换；“已发布目录”仍是独立只读盘点入口。
- [ ] 版本备注首屏保留使用建议、更新人、影响场景和摘要；详细变化、风险、必须确认和证据引用折叠在高级编辑中，保存按钮文案为“更新版本说明”。
- [ ] 库目录能看到已登记源库，不触发 discover 或 Catalog refresh。
- [ ] 库列表使用正式 `library_name`，不把 vendor 或中间目录当成库。
- [ ] 版本列表使用表格，超出区域后滚动，不把所有版本无限平铺。
- [ ] 版本状态显示扫描、对比和发布检查三类现有事实。
- [ ] 版本详情链接指向现有 `catalog/html/.../index.html`。
- [ ] 页面中文为主，专业状态值保留机器原名。
- [ ] 页面没有任意 shell 输入框。
- [ ] 版本概览提供“完整检查”，按扫描、对比、发布检查顺序执行；已有扫描证据时复用，不重复扫描。
- [ ] 库工作流提供“查看接入建议、生成处理建议、生成处理计划”。
- [ ] “执行完整计划”和“设为当前可用版本”是明确的写入动作，执行前需要浏览器确认。
- [ ] 人工确认与库维护提供包类型修正、审查门禁、审查记录、当前可用版本回退和预定义动作入口；写入动作必须有确认或必填审计字段。
- [ ] 运行设置集中提供哈希策略、解析并发、解析/排除类型、是否刷新详情页、补扫缺失证据、强制重扫和对比模式。
- [ ] 桌面顶部固定所选版本和运行状态；完整版本表在普通滚动区展开，日志详情默认折叠。
- [ ] 包类型修正默认折叠，提供短类型标记、目录包类型、阶段、完整包基线、上一有效版和默认对比设置。
- [ ] 版本处理区提供“联动文件核对”：文件变化来自已有 `file_diff.json`，按变化类型和视图类型筛选，并在固定高度表格内滚动。
- [ ] 选择有旧/新文件的一行后，页面自动显示两侧相对路径；新增、删除和未知类型只展示证据，不生成不可执行的深度核对。
- [ ] Liberty、Verilog、SPEF、DB、GDS、OAS 等轻量证据类型默认禁止完整内容读取；只有明确勾选完整读取后才提交深度核对任务。
- [ ] 扫描页参数只用于本次任务；设置页的目录、扫描默认值、发现默认值分别保存到配置并生成备份。
- [ ] 技术检查明确显示所选有效组合的组成版本；无基准时差异规则禁用，单组合规则可执行。
- [ ] 发布目录和方式先于检查、预演、实际发布按钮；参数变更后旧预演标记失效。
- [ ] 未得到当前版本及参数的成功预演前，不显示“确认并创建链接”；同名冲突的部分预演允许继续核对。新链接占全部时默认显示全部明细，而非空的“替换及异常”筛选。
- [ ] 失败的库级执行保留旧当前有效组合、已选组合草稿及预览，并保留失败状态与运行日志入口；失败不得被呈现为候选已生效。
- [ ] 刷新正式发布目录只更新盘点快照，不修改 RAW Catalog、当前有效指针或正式目录中的既有链接。
- [ ] 发布检查/预演与实际发布分开；只有显式确认的实际发布动作可以创建/替换链接，失败需显示逐文件或逐库结果。

## 短命令覆盖

页面不是第二套命令实现，而是对 `short_cli` 的受控入口。首屏提供日常动作，完整命令面在底部折叠区：

| 短命令 | Web 入口 | 说明 |
|---|---|---|
| `library list` | 左侧库目录 | 只读列表，不重复增加按钮 |
| `cat` | 刷新当前库目录 | 默认快速刷新；文件证据需显式勾选 |
| `scan` / `cmp` / `rel` | 版本概览中的版本操作 | 使用当前选中库和版本 |
| `next` / `intake` / `window` / `accept-window` | 人工确认与库维护 | 预演与写入分开 |
| `mark` / `library override` | 包类型修正 | 需要选中版本并确认写入 |
| `worklist` / `library discover` / `library accept` / `library apply` | 其他操作 | 工作区级入口，写入动作需确认 |
| `library add` | 其他操作 / 新增库登记 | 需填写正式库名和库根目录 |
| `fd` | 深度文件对比 | 可从文件结构选旧/新路径，也可手工指定不同文件名；服务端仍校验允许的路径范围 |
| `rv` / `review` | 审查记录 | 管理入口，结果仍写入同一运行记录 |
| `effective rollback` / `action` | 当前可用版本维护 | 高风险写入，必须填写或确认必要信息 |
| `init` | Web 首次连接引导 | 配置缺失时可在页面填写工作区和原始库根并初始化；也可用 CLI |

每个 Web 动作只会生成参数数组并调用既有 `short_cli`，不会接受任意 shell 字符串，也不会在页面加载时自动执行这些命令。

## API 检查

```bash
curl -fsS http://127.0.0.1:5000/api/health
curl -fsS http://127.0.0.1:5000/api/libraries
curl -fsS \
  http://127.0.0.1:5000/api/libraries/<LIBRARY>/versions
curl -fsS http://127.0.0.1:5000/api/workspace
```

- [ ] 未知库返回 404。
- [ ] Catalog 缺失返回 503，并说明配置/路径问题。
- [ ] scan、compare、release-check 只接受 Catalog 中已有的库和版本。
- [ ] next、intake、window、accept-window 只接受 Catalog 中已有的正式库。
- [ ] mark、override 只接受 Catalog 中已有的库和版本，并校验枚举值。
- [ ] scan/compare 的策略设置以参数数组传递，不拼接 shell 命令。
- [ ] 动作返回 `job_id`，不在 HTTP 请求中同步等待长任务。
- [ ] Job 请求保存为参数数组 JSON，不保存可执行 shell 字符串。
- [ ] Job 状态能返回 `QUEUED`、`RUNNING`、`COMPLETED` 或 `FAILED`。
- [ ] 最近运行区域显示任务状态、已用时、阶段和百分比；底层没有阶段百分比时显示“处理中”，不能显示虚假的 0%。
- [ ] 最近运行区域显示有上限的终端输出尾部和日志大小；长日志不被一次性读入页面。
- [ ] 终端输出区明确区分原文总大小和页面显示的尾部大小，避免把一次性截取误解为持续加载。
- [ ] 扫描任务能读取已有 `scan_progress_latest.json`，并把阶段进度呈现到运行区域；扫描外的任务没有进度文件时仍能显示终端尾部和用时。
- [ ] 发布检查、目录刷新等非扫描任务不复用上一扫描的 `scan_progress_latest.json`，避免把旧的 `scan finished: PASS` 当成当前任务进度。
- [ ] 服务重启后未被当前进程接管的任务显示为未知，不把旧的 RUNNING 状态伪装成仍在执行。
- [ ] 日志通过受控 API 路径读取，不能访问任意文件。
- [ ] 运行完成后可从输出或状态找到 `run_manifest.json`。
- [ ] 文件变化接口只读取选中版本已有的 `file_diff.json`，不递归扫描 RAW，也不读取文件内容。
- [ ] 联动文件核对使用服务端解析的旧/新版本绝对路径调用既有 `fd --old/--new` 入口；浏览器不能提交任意路径。
- [ ] 新增库登记可点击“浏览目录”，默认从配置的 `raw_root` 进入；选择目录后可直接回填库根目录。
- [ ] 目录选择器只返回允许范围内的目录，不列出文件，不接受越界路径或解析后落到范围外的符号链接。
- [ ] 已知库根使用“添加新库”：默认一次完成登记、应用库映射和目录刷新；完成后左侧自动选中新库。
- [ ] 单版本库允许直接登记，页面明确提示后续先扫描而非要求先做版本对比。
- [ ] 候选表中可使用“使用此候选”带入正式库名和库根目录；批量勾选登记只用于多候选确认。

## 运行观测验证

1. 打开控制台，展开“其他操作”，点击“查看全部工作清单”。
2. 选择一个已有扫描证据的版本，展开“版本处理”，点击“执行完整检查”；确认页面按扫描（复用）、对比、发布检查顺序运行，并在“最近运行”保留状态与日志入口。
3. 选择一个没有扫描证据的版本，点击“执行完整检查”；确认先扫描，扫描失败时不继续对比和发布检查。
4. 展开“库级流程”，分别查看接入建议、生成处理建议、生成处理计划；只有填写确认人并确认后，才允许设为当前可用版本。
2. 在“最近运行”中确认状态、用时、终端输出尾部和日志大小出现；工作清单没有扫描阶段文件时，进度应显示“处理中”。
3. 对选中版本执行“生成扫描”。扫描期间确认阶段、百分比和终端尾部会随轮询更新；完成后状态变为“已完成”或“失败”，并保留日志入口。
4. 刷新浏览器，确认最近一次任务仍可通过 `job_id` 查询；不要把刷新页面当成重新执行动作。
5. 任务目录中的 `stdout.log` 只检查尾部展示，完整日志通过“打开运行日志”入口按需查看。

## 反防御性设计

- [ ] 不引入数据库、调度器、WebSocket 或第二个后端。
- [ ] 不允许浏览器直接修改 `catalog.json`、`catalog_runtime.json` 或 scan/diff 事实。
- [ ] 不允许任意 shell 命令、任意路径和任意 Python 模块调用。
- [ ] 不因打开页面而全量扫描、全量对比或全量渲染。
- [ ] 不新增主审查页面；详情页仍复用现有 Version Detail。

## 手动验收流程

1. 打开库运行台，选择 `vendor_A.openroad_platform.openroad_asap7`。
2. 选择 `20260627_asap7`，确认版本表和右侧事实一致。
3. 打开版本详情页，确认 URL 落在现有 `catalog/html` 下。
4. 点击扫描或对比，确认出现 job 状态和运行日志。
5. 任务完成后检查 `run_manifest.json`，再刷新页面确认状态来自 Catalog/runtime。
6. 在运行设置中切换哈希策略和对比模式，确认只改变本次任务请求。
7. 点击“生成处理建议”和“生成处理计划”，确认默认只读且任务有日志入口。
8. 展开“包类型修正”，选择版本后检查默认值；提交修正前确认浏览器提示，并确认任务参数中没有任意 shell 字符串。
9. 在“版本处理”展开“联动文件核对”，按“变化类型”和“视图类型”筛选，选择一条有成对旧/新文件的记录；确认路径自动带入，运行后在“最近运行”查看任务和日志。
10. 选择 GDS、DB、Liberty 或 Verilog 记录时，确认未勾选完整读取会阻止任务；勾选后才允许提交，并且只对这一对文件执行。
11. 展开“新增库登记”，点击“浏览目录”，逐层进入目标库目录，点击“使用当前目录”确认回填；无需复制绝对路径。
12. 已知新库根时，展开“添加新库”，填写正式库名和库根目录后点击“登记并加入目录”；确认提示后，等待运行记录完成并确认左侧自动选中新库。只有一个版本时，先选择该版本生成扫描事实。
13. 不知道库根时，先执行“发现候选库”。对单项候选点击“使用此候选”带入添加表单；只有需要一次确认多项时才勾选后使用“登记已选库”。
