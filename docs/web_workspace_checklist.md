# 操作台信息组织验收

## 目标与边界

库管理员在同一个库和版本上下文中完成登记、分析与交付。页面按工作目的组织，不把独立动作伪装为必须依次执行的阶段。
本轮只重组 Web 模板、导航与样式；不修改 CLI 参数、扫描、对比、解析器、有效组合或发布事实。

## 内容归属

| 工作区 | 内容 | 不放入 |
|---|---|---|
| 库与版本 | 路径发现、正式与候选库、登记、新版本接入、属性修正与异常处理 | 扫描参数、发布结果 |
| 版本分析 | 扫描、对比、深度核对、审查记录、文件树、变化清单、版本备注 | 发布按钮、正式发布库查询 |
| 发布交付 | 发布查询、检查、预演、实际发布、覆盖核查、多库清单 | 扫描设置、包类型修正 |
| 独立设置 | 工作区目录、保存与恢复默认、数据路径 | 发布查询、异常回退 |

顶部库、版本、基准和运行记录共享。扫描、对比参数在对应动作旁设置；不复制表单，保存默认仍使用同一套字段。

## 库发现与登记验收（2026-10-09）

使用顺序：填写发现路径 → 发现候选库 → 核对库根、展开版本列表和文件类型 → 勾选登记。
发现路径只限定本次搜索，不修改全局原始库根；登记后自动应用并刷新目录。
识别不对时点击“修改库名 / 库根”，使用现有登记表单修正。手动编辑登记表后才需要“登记表维护”。

- [x] 默认允许单版本库，陌生版本名称根据文件类型进入候选。
- [x] 厂商、视图目录、source_package 不成为库；含命名版本的容器不作为一个交付实例。
- [x] 找到库根后停止进入交付内容发现其他库。
- [x] 每个交付目录最多检查 400 个条目、深度 4；不读取文件内容、不计算哈希。
- [x] 外层目录数及候选数达到限制，界面明确显示“搜索未完成”。
- [x] 发现不改正式登记；接受候选合并保留已有登记。
- [x] Web 从保存的快照读取完整版本列表和文件类型，不重新遍历原始目录。
- [x] 中文文件类型依据替代规则串和置信度。旧快照缺少依据时明确提示缺失。
- [x] 取消登记后必须手动应用的流程暗示；版本明细在有界滚动区完整换行。
- [x] 浏览器实测陌生单版本 / 双版本库：发现 2 项，原有 2 个库保留；展开、批量勾选、修正表单带入正常。
- [ ] 大型内网目录性能和供应商库边界人工验收。自动发现不能证明任意层次的业务含义。

旧 JSON 的 confidence 字段保留为 0，仅兼容旧读取端，不再计算评分。旧快照只有示例时不声称包含全部版本。
版本列表用于核查，不在本轮新增逐项版本排除配置。发现不改变当前有效版或正式发布链接。

验证：`PYTHONPATH=src python3 -m unittest discover -s src/lib_guard/test -p 'test*.py' -q`。
编译及前端语法检查：`PYTHONPATH=src python3 -m compileall -q src`、`node --check src/lib_guard/web/static/app.js`。
小规模模拟结果不能代替大型内网文件系统性能验收。
