# 面向 IP 使用者的版本报告

Status: current

## 目标与边界

- 读者：拿到静态 HTML 的 IP 使用者，不要求了解 CLI 或内部数据模型。
- 判断：本版交付什么、相对哪个版本变化、哪些结论已经有证据、哪些仍待核对。
- 输入：既有扫描、对比、版本备注与代表文件核查结果。
- 输出：Version Detail 的文字、展示分类、文件树与筛选。
- 不改：扫描/匹配算法、解析器、命令、发布条件、有效版选择；不新增使用判断来源。

## 实施

1. 版本备注保持最高阅读优先级；变化矩阵与版本摘要并列。
2. 摘要改为主要变化、使用影响、需要确认，按使用场景合并说明。
3. 去掉 `?+`/`?-`；待核对文件按本版、基准版分别计数，不归入新增/删除。
4. 矩阵和文件树共用 `build_ip_change_projection()`；不直接把原始 diff 状态作为读者分类。
5. 文件树按已有逻辑路径映射还原实际目录，避免同一文件在逻辑路径与扫描路径重复出现。
6. 文件信息检查与内容检查分开说明；原始 JSON 入口折叠，保留绝对路径复制。

## 验收清单

- [x] `108` 明确表示本版待核对文件，不使用 `?+` 或“未匹配新侧”。
- [x] 待核对本版/基准版不相加冒充唯一文件数量。
- [x] 待核对文件不在文件树中再次标成新增/删除。
- [x] 基准版待核对文件不进入“当前交付”筛选。
- [x] 逻辑路径与扫描路径对应的文件仅显示一次。
- [x] 原始绝对路径仍可复制；缺少基准源目录时不猜测路径。
- [x] 首版显示交付信息，不伪造零变化比较。
- [x] 缺少对比不声称“无变化”；仅文件信息证据不声称内容相同。
- [x] 人工备注和已有 IP 判断来源不变；不触发补扫/发布。
- [x] 桌面浏览器验证矩阵筛选、文件树筛选、路径入口、代表文件报告。
- [x] 全量测试通过；检查既有语义验收断言未被删除。

## 已知限制

待核对仍来自现有包根目录兜底机制，并不是逐文件完成身份验证后的结果。本轮修正报告表达与数据展示一致性，不宣称已解决全部匹配问题。使用影响仅能说明涉及的视图和检查范围，没有具体字段证据时不生成虚构的工程建议。
