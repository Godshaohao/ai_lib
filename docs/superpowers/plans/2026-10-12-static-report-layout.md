# 静态报告整理计划

目标用户：库负责人和 IP 使用者。主判断：本次交付内容、变化范围、负责人备注及需要核查的文件。
输入：已有目录、运行状态、扫描和对比证据。输出：重新生成的目录、库页和版本详情 HTML。
禁止扩展：不重新扫描，不改 parser、对比算法、有效版规则或发布规则，不增加主页面和依赖。

## 循环检验结果

1. 发现页面模板忽略 nav：显示真实导航，详情到总目录使用 ../../../../index.html，到库页使用 ../../index.html。目录首页不显示空目标的伪入口。
2. 发现库页使用 file:// 链接：catalog_workspace_report.py 改用相对报告链接；catalog_report.py 统一解析输出目录，覆盖相对输出路径的回归。
3. 发现首版暗示已对比：version_review_render.py 在首版只展示“本次交付 / 扫描证据”，不展示零差异和变化筛选。
4. 发现矩阵数量入口仅跳锚点：version_file_evidence.py 复用原有筛选，点击 LEF 入口后显示当前交付的 27 个 LEF。
5. 发现目录首次初始化早于脚本定义：product_theme.py 在 DOMContentLoaded 后初始化；搜索不存在的库从 1 库 / 2 版本变为 0 / 0，重置恢复。
