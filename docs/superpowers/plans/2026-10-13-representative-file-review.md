# 代表文件深度核查接入版本详情

Status: current

## 已确认设计

目标用户：核查新 IP 版本的工程师。
每种文件类型由人工选择一组旧文件与新文件；不同名允许。
执行既有 fd 后点击加入详情，保存备注，只替换该类型的当前选择。
生成候选或保存核查结果不改变 usage decision、版本 diff、当前有效组合或发布门禁。

## 实施顺序

1. 测试先行：真实 fd 结果保存、同类型替换、源文件变化提示、删除 Web job 后重建。
2. review/representative_files.py：独立持久化选择，复用已有 JSON 的小摘要；保留报告副本。
3. render/version_file_checks.py：表格展示范围、类型、双方绝对路径、证据能力、主要变化和备注。
4. Web：从已完成且属于当前版本的 file-diff 任务保存；不接受浏览器传入结论或产物路径。
5. 单版本 render fast 刷新；页面失败明确告知记录已保存，原页面保留。
6. 复用现有 Liberty/DB 配套清单，加入详情页，不误称 Liberty/LEF pin 检查。

## 验收

- 不重新扫描、不触发批量 hash；每类型一组、各类型互不覆盖。
- FAILED/UNSUPPORTED 结果不能加入；缺少源文件状态不能声称新鲜。
- 元数据/哈希对比不声称语义安全；代表文件不代表整个视图通过。
- 保存记录与报告不依赖 HTML 或 Web Job；删除投影可重建。
- 路径、备注 HTML 转义；job 不能跨库或跨版本挂载。
- unittest 全量、compileall、JS 语法和真实浏览器操作验证。

## 评估边界

本轮不实现跨视图 pin 一致性、corner 自动关联、自动审查结论。
摘要只取对比能力、已提取字段、变化类别和少量定位；时序全表与原始 JSON 留在详细报告。
