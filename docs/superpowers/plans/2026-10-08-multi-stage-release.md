# 多库阶段交付实施计划

**目标：** 管理员勾选已确认有效组合，在指定 lib_NL2.1.0 等阶段目录实际创建展平链接；管理列表只列当前阶段目录，不列备份。

**边界：** 不改扫描、对比、解析器或有效版接受规则。不增加数据库、短命令别名。复用发布器的锁、备份、预检、后检和回退。Web 任务复用现有子进程及日志。

1. 为多库 manifest 构建和实际发布增加隔离测试：两库两文件、预演无链接、覆盖保留当天备份、同名冲突、缺少有效指针。
2. 新增 release/set_publish.py，将当前有效 manifest 中的明确文件清单汇总，不重新遍历 RAW；release_components 仅描述组件，不重复参与文件遍历。
3. Web 注册两个工作区动作：多库预演、实际发布。请求限制为已登记库、配置发布根、合法阶段名称。发布确认不等同于自动接受有效版本。
4. 复用发布结果投影和任务日志；多库选择区提供阶段、最新指针、预演、确认发布。完成后刷新发布目录索引。
5. 发布目录索引增加阶段投影，仅读取非历史实际阶段 manifest；历史库查询兼容保留，但默认管理表按阶段展示。
6. 运行发布、Web、架构约束测试；浏览器隔离演练两库交付与覆盖，检查实际链接与旧交付保留。

验收：实际发布有文件链接、后检 PASS；最新指针正确；冲突及失败不替换旧交付；其他阶段仍存在；历史目录不进入默认管理表。
