# 双栏文件对比设计

Status: current

## 目标

让库管理者在一次文件深度对比后，直接像使用 gVim diff 一样核对旧文件和新文件，不再在结构化摘要、原始 HTML 和 JSON 之间往返。

## 用户与判断

- 用户：库管理者、IP 视图审查者。
- 场景：从版本变化清单选择一对文件，确认接口、约束或物理视图的具体变化。
- 判断：哪些文本行新增、删除或修改；变化是否与结构化摘要一致。
- 后续动作：返回版本变化清单继续核对，或导出对比证据。

## 设计

现有 `file-diff` 继续生成解析摘要和语义差异。`raw_text_diff.html` 改为自包含的桌面双栏查看器：顶部展示文件对象、变化块计数、显示模式和上一处/下一处；正文将旧侧与新侧按 `SequenceMatcher` 操作码对齐，显示独立行号、变化类型和文本。相同段落默认保留少量上下文，用户可切换完整文件。

双栏共享一个滚动容器，因此垂直和水平位置天然同步。每个变化块具有稳定编号，可使用按钮或 `[`、`]` 键跳转；`n` 切换仅看变化，`f` 切换完整文件。页面离线可用，不加载第三方脚本或字体。

## 边界

- 不修改 scan、版本匹配、内容判定或发布门禁。
- 不提供编辑、合并或写回文件能力。
- 不引入 Monaco、CodeMirror 或其他依赖。
- 二进制文件仍只显示元数据/哈希证据，不伪造文本差异。
- 超长文件仍由现有大文件策略控制；查看器不主动读取更多数据。

## 类型能力与参数

单文件深度对比必须先说明“本类型比较哪些工程参数”，再提供证据入口。

- 结构化文本类型：LEF、Liberty、Verilog、CDL、SDC、UPF、CPF、SPEF、Waiver、IBIS、PWL、SNP、CPM。报告提供结构化参数摘要、字段变化、Markdown 摘要和双栏文本对比。
- 二进制类型：DB、GDS、OAS、NDM。报告只提供文件大小、内容哈希、解析器状态和原始交付路径；不得生成或链接双栏文本对比。
- 未支持类型：报告明确显示当前没有结构化参数、只保留元数据级证据，不能把该状态伪装成“内容相同”。

参数集合使用代码中的固定类型映射，而不是临时从解析 JSON 猜测。这样页面、Markdown 和导出包使用同一个可审计口径。

## 验收

- 修改、新增、删除行能够双栏对齐，并同时具有颜色和文字标识。
- 支持上一处、下一处、仅看变化、完整文件和键盘操作。
- 路径过长不挤压正文；正文具有固定表头与有限视口。
- Web 运行结果把“双栏文本对比”作为主要产物入口，结构化报告与导出包保留。
- 真实 LEF 与 Verilog 样例在桌面浏览器完成截图和点击验证。
