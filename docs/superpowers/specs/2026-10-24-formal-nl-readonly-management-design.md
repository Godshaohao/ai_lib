# 正式 NL 只读管理设计

## 目标

在独立 `src_qor` 工作台中，为每个已登记 IP 提供正式 NL 目录的只读查询和核查入口。复用 `effective_file_tracker.py`，让维护者能快速回答：该 IP 在哪些 `lib_NL*` 阶段出现、链接指向哪里、能看到哪些 View/Corner 文件、是否有断链或多重匹配。

本功能不修改正式目录，不创建、替换或删除链接；不把文件存在、链接有效或数量齐全解释为 IP 可用或正式放行。

## 现状与边界

- `effective_file_tracker.py` 已支持按 IP 名称发现正式目录中的链接/来源，并生成 JSON 与 Markdown 盘点结果。
- `review_runner` 已有 `formal_nl` 检查项，但入口是逐 IP 的检查配置；它不是正式 NL 的目录总览。
- 正式 NL 阶段名仅用于显示和既有脚本的路径排序，不作为 IP 有效性或发布结论。
- 继续使用 YAML/JSON 文件，不增加数据库、常驻后台任务或第二套正式库事实源。

## 页面与操作

在现有独立工作台增加“正式 NL”只读工作区，不改 RAW Discover 的含义。

1. 选择已登记 IP，显示其目录名及 RAW 来源路径。
2. 输入或选择正式 NL 根路径；支持根路径包含多个 `lib_NL*` 阶段，也支持直接指定单个阶段的 `IP` 目录。
3. 执行“刷新盘点”，调用现有 tracker，产出可重复生成的 JSON/Markdown 报告。
4. 总览按阶段列出匹配状态、正式链接路径、解析到的目标路径、可见文件总数及 View/Corner 数量。
5. 详情表按 View 展示文件路径和文件名 Corner 线索；断链、同阶段多目标、未解析来源单独列出。
6. 页面标示“只读路径盘点；不判断必需性、内容正确性或放行”。报告失败时保留上次成功结果并显示本次失败信息。

正式根路径可保存到该 IP 的现有工作台 YAML 配置中，供下次进入复用；这只写工作台配置，不触碰正式 NL 路径。报告保存到工作台输出目录，不写入正式目录。

## 数据与实现边界

- 复用 `discover_formal_ip_links()`、现有文件清单与 View/Corner 统计逻辑；不复制扫描/链接解析算法到 Web。
- Web 只负责 IP 与路径选择、运行状态、摘要和明细呈现、报告下载。
- 所有路径解析结果都保留输入路径和解析目标，按链接/路径的可见事实描述。
- `LATEST`/`SECOND_LATEST` 等既有标签只作为目录名排序结果展示，并注明排序依据；不能叫“已生效”或“当前可用”。
- 禁止任何指向正式根目录的写操作；本阶段无 Apply、发布、链接修改按钮。

## 验收

- 多阶段正式根目录可列出目标 IP 的阶段、链接目标、View/Corner 文件计数。
- 单阶段 `lib_NL*/IP` 根可进行只读盘点。
- 不存在的路径、无匹配 IP、断链、同阶段多目标均显示明确状态，不产生成功结论。
- YAML 保存和报告生成都发生在工作台配置/输出路径；正式目录的文件、目录和链接在执行前后保持不变。
- 页面可重新打开并恢复所选 IP 与正式根路径；工作台刷新不要求重跑既有扫描或技术检查。
- 现有 `formal_nl` 检查、RAW Discover、其他检查结果行为不回归。

## 本阶段不做

- 创建、覆盖、删除或重命名正式链接。
- 将正式目录与 Effective/候选组合自动比较或切换。
- 自动推断必需 View、Corner 或完整性门禁。
- 解析 LEF/Liberty 等文件内容；此处只呈现 tracker 已有的路径、类型和命名线索。
